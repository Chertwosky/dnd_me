# D&D Game Table — MVP

Веб-платформа для онлайн-сессий D&D с упором на игровое поле, токены, карточки персонажей, генераторы лута и событий, а также встроенную справочную панель в духе удобного структурированного D&D-справочника.

## Идея продукта

Продукт позиционируется не как «ещё один справочник», а как **игровой стол + мастерская мастера**:

- мастер создаёт комнату и управляет сессией;
- игроки заходят по invite-ссылке и взаимодействуют с картой;
- справка, карточки, броски, лут и события доступны прямо внутри комнаты;
- контент и UX ориентированы на быстрый темп реальной игровой сессии.

## Ценность MVP

MVP должен позволить провести простую онлайн-сессию без переключения между несколькими сервисами.

### Минимальный сценарий мастера

1. Создать комнату.
2. Загрузить карту.
3. Расставить токены.
4. Открыть карточки персонажей.
5. Бросать кубы.
6. Выдавать случайный лут.
7. Запускать случайные события.
8. Открывать справку в боковой панели.

### Минимальный сценарий игрока

1. Зайти в комнату по ссылке.
2. Видеть карту и свои токены.
3. Перемещать только свой токен.
4. Открывать лист персонажа.
5. Бросать кубы.
6. Получать лут и эффекты событий.

## MVP-функциональность

### 1. Комнаты и роли

- комнаты по invite-ссылке;
- роли: мастер, игрок, наблюдатель;
- базовая модель прав на управление объектами.

### 2. Игровое поле

- загрузка изображения карты;
- сетка поверх карты;
- масштабирование и перемещение;
- токены персонажей и NPC;
- drag-and-drop перемещение токенов;
- измерение расстояния;
- слои: карта / объекты / заметки / fog of war.

### 3. Карточки персонажей

- загрузка JSON, PDF или изображения листа;
- базовые поля: имя, класс, раса, HP, AC, speed, stats, inventory, spells;
- быстрый просмотр по клику на токен;
- редактирование владельцем или мастером.

### 4. Кубы и рандом

- d4, d6, d8, d10, d12, d20, d100;
- быстрые команды вида `/roll 1d20+5`;
- лог бросков в комнате.

### 5. Генератор лута

- таблицы случайного лута;
- категории: обычный, редкий, магический, расходники, золото;
- пользовательские таблицы мастера;
- выдача лута игроку или в общий сундук.

### 6. Случайные события

- наборы событий по сцене: таверна, дорога, подземелье, лес, город;
- вероятности выпадения;
- эффекты: текст, бафф/дебафф, спавн NPC, находка, ловушка;
- запуск одной кнопкой.

### 7. База знаний

Быстрый поиск и показ справки в боковой панели по:

- классам;
- расам;
- заклинаниям;
- монстрам;
- предметам.

## Что брать за ориентир

За основу UX можно брать:

- структурированность справочника;
- быстрый поиск по сущностям;
- генераторы и игровые инструменты;
- карточный формат подачи материалов.

## Что нельзя копировать 1-в-1

Не следует копировать:

- дизайн;
- тексты;
- базу контента;
- иконки;
- структуру страниц как уникальное произведение.

Правильный путь — брать **идею UX**, а не копию реализации.

## Рекомендуемый стек

### Frontend

- Next.js;
- TypeScript;
- Tailwind CSS;
- Zustand;
- TanStack Query;
- Konva.js.

### Backend

- Next.js App Router + Route Handlers / Server Actions для MVP;
- PostgreSQL;
- Prisma;
- Redis;
- Socket.IO.

### Инфраструктура

- S3-совместимое хранилище для карт, аватаров и файлов карточек;
- email magic link и/или OAuth;
- деплой фронта и API в одном проекте на раннем этапе.

## Архитектурная идея

- **frontend-first MVP** с единым приложением на Next.js;
- realtime через Socket.IO для комнаты и карты;
- персистентные сущности в PostgreSQL через Prisma;
- Redis для presence, быстрых событий и очередей;
- файлы карт и карточек в S3-совместимом хранилище.

Подробности описаны в `docs/architecture.md` и `docs/mvp-spec.md`.

## Риски

- слишком широкий MVP;
- лицензирование D&D-контента.

## Практичный подход к контенту

- сначала делать движок и пользовательские данные;
- не вшивать официальный контент без проверки лицензий;
- строить справочный модуль на собственных или разрешённых материалах;
- при необходимости использовать ссылки или интеграции вместо копирования контента.
